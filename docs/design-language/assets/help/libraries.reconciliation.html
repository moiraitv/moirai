Missing media and conflicts

Moirai does not immediately delete indexed media when a scan suddenly loses a meaningful part of a library. The missing records enter reconciliation so an accidental unmount or incorrect path does not silently damage schedules.

Library source change needs review means the configured media path or detected source identity changed. Open Review, check the candidate path and scan results, and accept it if it is the intended source. This can require approval even when no indexed items are missing; the review is about the source change, not the number of removals. After approval, Moirai scans the new source before updating the index. Source approval and missing-media notices appear in this dedicated alert rather than being repeated in Library scan needs attention. Other scan problems, such as an incomplete scan or unreadable media, still appear in the scan alert; scan history retains all diagnostics.

If the entire source path becomes inaccessible, Moirai shows Media source may be offline and retains the indexed media. This simulated example shows a library whose /media/movies path is unavailable, as it might be after a disk is disconnected or a network mount drops.

Check the source mount and permissions first. If the files are still meant to exist, restore access and scan again. Moirai can then heal path-only moves or confirm that the original records remain.

If the files were deliberately removed, open the reconciliation review and confirm the proposed removals. This is permanent for the indexed records, although scanning the files again can recreate them.

The dashboard also reports data conflicts such as ambiguous identities. Resolve the source metadata or folder layout, then synchronize the affected library. Existing committed guide entries can remain playable from their captured metadata while new scheduling avoids unavailable content.
