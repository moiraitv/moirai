Design reference

Local snapshot of the bundled application guide. Review state is preserved.

Backup settings

Open Settings → Backups to manage automatic backup policy and saved archives. Use the tab footer’s Save or two-step Reset for policy edits. Creating, importing, restoring, downloading, and deleting archives are separate actions.

Backup & Restore

Backups preserve configuration, the library index and its IDs, channel icons, custom guide artwork, and uploaded fallback videos. They exclude library media files, generated thumbnails and other caches, logs, passwords, sessions, and API keys. Keep media mounted at the same paths when moving to another installation. Separately mounted folders for channel icons, guide artwork, or fallback videos stay mounted during restore; their contents are replaced by the backup. Saved AI preferences are included, but you must enter credentials again.

Backup filenames include their creation time in UTC (Z) and a unique ID, for example moirai-2026-10-17T21-15-30.123Z-<id>.zip. This applies to files in the backup folder and downloads; existing backups remain usable.

If a backup reports Permission denied, make the backup folder readable, writable, and searchable by the container’s user. For a host bind mount, follow the folder ownership and permission setup. For read-only storage, use a writable volume mount; for storage is full, free space on that volume before retrying.

Automatic Backup

Automatic backups are enabled by default, run every 1 day at 3:00 am in Moirai’s configured time zone, and retain 7 automatic backups. Expand Automatic Backup to change Backup interval (days) or Automatic backups to retain, then choose Save in the Backups footer. If Moirai is offline at the scheduled time, it waits for the next scheduled run rather than creating catch-up backups.

The automatic backup section shows the saved policy summary. Expand Automatic Backup for the schedule, time zone, next run, and storage directory. Saved backups appear in the table under Backups; select Created to reverse their date order. Backups can use a separate Docker volume. If an upgrade recovery backup fails, Moirai continues the upgrade and shows a warning in Settings; a restore requires its pre-restore recovery backup to succeed. Use the warning’s × button to dismiss it; dismissal is remembered across page reloads and restarts. A warning also clears when its backup or cleanup succeeds on a later attempt. A new failure shows a new warning.

Backups

On the Backups tab, use Create Backup to save a manual ZIP or Download beside a saved backup to export it. Import Backup uploads a ZIP for validation. For a saved backup, choose Restore, then confirm Validate Backup. A dialog shows the current validation stage—archive integrity, database reconstruction, configuration checks, or managed asset checks—and either an explanation of the failure or the replacement summary. Closing validation abandons the restore flow; the check finishes in the background without changing configuration.

Review and restore

Review the filename, creation time, backup type, application version, size, and library, media-item, and channel counts. Choose Restore and Restart only when you are ready to replace the current configuration. Cancel Restore closes the review without replacing anything. If validation fails, use the displayed reason and request ID to check the server logs; try another backup or update Moirai when the archive requires a newer schema.

Restoring replaces the saved configuration and briefly stops playback while Moirai restarts. Once restore preparation succeeds, Moirai completes the restart even if your browser disconnects. Reconnect when it is ready. Your current administrator account is preserved, but existing sessions are invalidated and you must sign in again. Unsaved Settings drafts are discarded only after confirmation. Validation failures leave the current configuration untouched. If an interrupted restore cannot finish, check storage permissions and free space, then restart Moirai to resume it.

Retention and deletion

Manual backups stay until you delete them. Restoring first creates a Pre-restore recovery backup, which also stays until deleted. Upgrades attempt a recovery backup before any database updates; only the newest 3 Upgrade recovery backups are kept. These limits are independent of automatic backup retention. Choose Delete beside a backup, review its name in the confirmation dialog, then choose Delete Backup to remove it permanently. Choose Keep Backup or press Escape to cancel. Unreadable archives appear with a warning and can still be deleted; healthy backups remain available.
